# 抖音 AI 电台直播系统（airadio）

读稿 AI 主播：把直播稿用**阿里百炼 CosyVoice** 流式合成播放，同时实时监听**抖音直播间互动**（进场/关注/点赞/礼物/评论），在**句子边界**随机定时插播互动话术。音频从扬声器外放（或网页播放页），用手机麦克风进直播间——一个人一部备用手机就能开播。

```
抖音直播间(webcast WSS) → 互动事件队列 → 调度器(句边界+随机窗口)
                                      ↑
直播稿(.txt, 带标记) → 句子编译 → 逐句 TTS(百炼) → 音频块 → 扬声器/播放页 → 开播手机麦克风
```

## 快速开始

```bash
uv sync                                   # 装依赖
export DASHSCOPE_API_KEY=sk-xxxx          # 阿里百炼 API Key

# 1) 验证直播稿标记（不连直播间）
uv run pytest tests/ -q

# 2) 全流程试运行（不合成音频，只验证采集+调度）
uv run python -m airadio --room <直播间号> --script scripts/demo_script.txt \
    --sink dry --window 8,15 --min-gap 6 --loops 1

# 3) 正式运行：合成音频写到 out/chunks，浏览器播放页外放
uv run python -m airadio --room <直播间号> --script scripts/demo_script.txt

# 4) 另一终端：播放页（手机/电脑浏览器打开 http://本机IP:8000，点"开始连续播放"）
uv run python web/serve_player.py --port 8000

# 或者本机直接外放（有 ffplay 的机器）
uv run python -m airadio --room <直播间号> --script scripts/demo_script.txt --sink ffplay
```

## PC 端单机版（推荐：一台电脑直接跑，不用登录、不用前后端部署）

```bash
uv sync                                  # 装依赖（只需一次）
uv run python web/app.py                 # 双击/一条命令启动，浏览器自动打开 http://127.0.0.1:8019
```

单机版特性：**免登录**（右上角显示「本机单机版」）；关掉页面电台也不会停，只有点「停止」才停；
`Ctrl+C` 退出程序同时停电台。参数、提示词、音色都先在各选项卡配好，**只有点最下面「开始连续播放」
才会弹出开播向导**（不会一进来就弹）。

开播流程：AI生成选项卡 → 填大模型 + 粘贴保存「直播内容框架提示词」（可存多套）→
点「开始连续播放」→ 向导里选一套提示词「开播前生成新稿」→ 生成完直接开播。
直播中当前稿播到一半（默认 50%，可改 10–90%）后台自动写下一稿，播完自动接上；
**AI 稿只用一次，用完即弃，不进稿子库**，也不会重播。

默认播音音色方向：中年男性 55 岁左右、稳重略带沙哑（关键字 `male55`），
每开一场自动生成新的音色名（关键字 + 时间码）；点「跳过，用现有音色」则沿用上一场。

## 手机/多人云端版（要账号才用这条）

一条命令起服务，手机连同一 WiFi 浏览器打开 `http://<本机IP>:8010` 就是完整控制台：

```bash
uv run python web/console.py --port 8010            # 打开先进登录/注册页；管理后台 /admin
uv run python web/console.py --port 8010 --idle 90  # 空闲 90 秒无请求 ⇒ 该用户的电台自动停止
```

### 多用户 · 登录 · 管理后台

- **每个登录用户一套电台**：自己的直播间、稿子、话术、昵称规则、音色、播放进度、manifest 与日志互不影响（`data/users/<用户名>/`、`out/chunks/<用户名>/`）。两个人同时打开同一地址不再是同一个电台。
- **注册要审批**：注册后状态是「待审批」，不能登录也不能用任何 API；管理员在 `/admin` 点「批准」后才能用。**「停用」的账号任何 API 都返回 403**（正在跑的电台会被立即踢下线），管理员可重新启用。
- **管理后台 `/admin`**：管理员账号 `admin`（初始密码由 `--admin-password` 或 `AIRADIO_ADMIN_PASSWORD` 给，可在后台改；密码只存 pbkdf2 哈希，明文不落盘）。后台能：批准/停用/启用/删除账号、给用户重置密码、看当前有几个电台在跑（房间、稿、空闲秒数、TTS 次数/复用次数）并直接停掉某个人的电台。
- **页面关了就不再挂后台**（三保险）：① 页面关闭/刷新时前端 `fetch('/api/leave', {keepalive:true})` 立刻停；② 服务端回收线程：超过 `--idle` 秒没有任何请求（= 没有心跳）就停掉播放线程和抖音采集；③ 用户可在「我的账号」页手动「立即停止我这个电台」。主动**暂停**的电台不按空闲回收（那是明确要保留，而且它不请求百炼）。
- **每开一场都问一次音色**：「开始新直播」向导里填直播间号、选稿（默认稿 / 稿子库 / 粘贴新稿），然后**填一个音色关键字生成这一场专属的新音色**（关键字会自动展开成百炼的音色描述：温柔女声 / 沉稳男声 / 明亮有活力 / 平稳讲解…），也可以跳过沿用上次用的音色。
- **控制台改成选项卡**：`实时互动 / 稿子 / 音色 / 话术 / 插播参数 / 我的账号 / 日志`，每页底部都有各自的**保存按钮**（改了不保存不会生效），上次停留的页签刷新后还在。


控制台功能（全部实测可用，API 均有回归验证）：

- **实时互动流**：弹幕 / 礼物 / 灯牌(粉丝团) / 关注 / 进场 / 点赞 实时滚动，含昵称、礼物名、数量、时间；已插播的话术也单独列出。
- **每类互动独立频率**：礼物 / 弹幕 / 灯牌 / 关注 / 进场 / 点赞 各自一个"随机插播区间"输入框（留空=跟随全局默认），到点只插最新的几条（优先级 礼物>弹幕>灯牌>关注>进场>点赞）。
- **互动话术自己写（每类多条随机播）**：页面上每类互动一个文本框，**一行一条**，播放时随机选一条，随时改、保存即生效并持久化（存 `data/library.json`，重启还在）。
- **全局占位符**（互动话术、`[[待插:…]]`、报时话术共用同一套）：`[昵称] [月] [日] [年] [时] [分] [秒] [时点][时分] [星期] [时段] [礼物] [数量] [内容]`，兼容旧写法 `{nick} {gift} {count} {content}`；页面有占位符按钮点一下就插入，并显示实际替换例子（`[时点][时分]` 读成"19点05分"，分钟自动补零）。
- **读昵称的规则**：可勾"只读汉字"（emoji/字母/数字跳过）+ "最多读几个字"。例：`兴旺🌹的大刘啊` 勾汉字 + 4 字 → 读"兴旺的大刘"；全 emoji 昵称读"直播间的朋友"，不会出现半句。
- **随机报时**：开关 + 间隔下限/上限秒 + 报时话术（一行一条随机选，里面写时间占位符）。到点就在句子边界插播；若那一刻正好有互动，就同一次插播一起说（热门房间不会被互动挤掉）。
- **直播稿编辑**：载入当前稿 → 手机里改 → `保存（下一段生效）` 或 `保存并立即从头播`；带保护块 / 停顿 / 必播话术标记的语法校验，空稿直接报错拒绝。
- **语音模型自由切换**：页面模型下拉列 cosyvoice-v3.5-flash / v3.5-plus / v3-flash / v3-plus / v2，音色下拉随模型变化；系统音色清单是**用你这个账号实测过的**（`uv run python scripts/probe_voices.py` 重测，结果存 `data/verified_voices.json`）。选错搭配服务端直接拦并说明原因。
  - 实测事实：**cosyvoice-v3.5-flash / v3.5-plus 没有任何系统音色**（填 `longanyang` 被拒 `Engine return error code: 418`），只能用"提示词设计"或"录音复刻"生成的音色；v3-flash 实测 35 个、v2 实测 14 个系统音色可用。
  - 音色**绑定生成时的模型**，不能跨模型复用；换模型要重新生成音色（缓存 key 含模型，旧音频自动失效重生成）。
- **生成新音色两种方式**：① **只填提示词**（描述性别/年龄/语气/用途）→ 生成 `…-vd-…` 音色，不用录音；② 录你自己的声音（复刻）→ 生成 `…-{prefix}-…`。生成后自动选中并试听；已有自建音色列在音色下拉最上方（🎙 标记）。
  - 录音失败会在**本地先体检**再告诉你原因：录 <4 秒 → "录音只有 x 秒，太短"；录了但几乎没说话 → "听不到说话（有效语音 x 秒）"；`prefix` 必须是**英文小写字母数字且 <10 位**（中文名会被百炼拒）。
- **音色管理（不用开播也能管）**：「音色」页的「我生成的音色」列表直接把**生成时用的提示词当名字**显示（百炼自己返回 `voice_prompt`），每行都有「试听 / 用它播（设为当前音色，在播立即生效）/ 改名 / 删除」。列表**翻页取全**（百炼 `list_voice` 默认只给 10 条，以前自建音色会"看不到"）。生成成功会明确告诉你并当场播放百炼返回的样例音，同时自动设为当前音色；不是这个页面生成的音色删除前要再确认一次。
- **顶部常驻音色徽章**：顶栏 `🎙 音色名` + 下方一行写明「当前音色 / 属于哪个模型 / 正在用还是下次开播用」；音色与模型不匹配会直接标红说明（跨模型用音色百炼必失败）。开播向导里既能"按关键字生成新音色"（默认模型 `cosyvoice-v3.5-flash`，默认方向中年男性 55 岁稳重沙哑），也能直接从下拉里**选一个已生成的音色**开播（选了就不会再生成新的）。
- **暂停就是真的停**：暂停/继续都会递增播放代次并让浏览器清空已排好的音频；服务端暂停期间前端不再排播。同一台电脑开多个页面/标签时只有一个标签出声（localStorage 抢占锁，6 秒没心跳自动接管），不会出现"两个音色重叠"。
- **播放控制（都是立即生效，不会等当前这句播完）**：暂停 / 继续 / 跳当前句 / 从头重播 / 切直播间。服务端每次重定位都会递增"播放代次"（`playback_epoch` + `play_start_chunk`），浏览器据此**清掉已排好的音频队列并从新位置接播**；服务端的节拍等待改成可被叫停（旧的 `time.sleep()` 要等一整组播完才响应，这就是"点了从头重播还要等半天"的原因）。自动播放开关会记住：刷新页面后继续自动播放，并从当前进度接播（不重播整轮历史）；浏览器要真人点一下才允许出声时会明确提示。每个按钮都有提示条反馈，处理中变灰不可重复点。
- **预生成控制**：可设"自动提前预生成 N 句"（默认 3，边播边把后面几组先合成好），也可手动"预生成 N 句"或"预生成整稿"。**提交新稿不会一次把整稿提交给百炼**——默认按需合成；点"预生成整稿"才一次合成完，之后循环全程零请求。顶部显示「播放进度 第 x / y 段」和「音频就绪 ready/total」进度条。
- **音频只生成一次、只下载一次**（服务端变薄、客户端不再重复取字节）：
  - 服务端两层缓存：内存 + 磁盘 `out/chunks/cache/<模型+音色+语速+文本哈希>.mp3`。**重启服务也不再请求百炼**，页面"音频就绪"重启后仍是 19/19（实测重启后 `tts_calls=1`（只有互动插播）、`cache_hits=11`、`disk_cache_hits=11`）。
  - 播放块按**音频内容哈希**落文件（`out/chunks/audio/<hash>.mp3`）+ `Cache-Control: public, max-age=31536000, immutable`：同一内容循环到第 N 遍不重复写盘、浏览器第二轮起直接命中本地缓存。实测同一 mp3 取两次：第一次 106,933 字节 / 679ms，第二次 **0 字节 / 3ms**。
  - 页面上直接显示：`服务端音频复用 N 次（其中 M 次来自上次运行）· 避免重复写盘 x KB`。
  - 自动预生成也走同一份缓存（含磁盘命中），所以"重启后接着播"不会重新排队生成。
- **状态轮询变轻**：`/api/state?lite=1&log_after=<游标>` 只回新增日志、不带话术配置；前端本地累积日志。实测响应从 2868 字节（整段）降到 1102 字节（稳态一次轮询）。
- **连贯播放（无停顿）**：三处一起处理。① 连续正文句**合并成一次 TTS 任务**（默认 2 句一组，页面上可调 1–6）——组内没有静音、语气连贯；② 播放节拍用**真实音频时长**（纯 Python 解析 MP3 帧，与 ffprobe 校准到 20ms），不再按字数估算；③ 自动**裁掉每块首尾静音**（百炼每块尾部实测 0.25–0.65s）。浏览器侧改用 Web Audio 排程接播，段间接缝按 manifest 的 `gap_before_ms` 对齐。实测块间空隙从 1.4–2.2 秒降到统一 0.15 秒（=「句间停顿」参数值，设 0 就首尾相接）。
- **稿子库（只放用户自己的稿）**：默认只保留 `相亲女`（落文件 `scripts/default_script.txt`，启动即用它，不需要在页面上再点一次）。每套稿可「载入编辑 / 播放这稿 / 删除」，手动稿可「存进稿子库」，也可以直接**选 .txt 文件上传**成一套稿。存 `data/library.json`。话题库与"生成新稿"已从控制台移除（代码 `airadio/generate.py` 与 `/api/generate` 保留，需要时可再开）。
- **不自动轮换**（默认）：当前稿播完就从头循环。多稿轮换的开关和"按行/按分钟切"UI 已移除；`airadio/orchestrator.py` 的轮换能力与 `/api/rotate` 保留，需要多稿轮播时再开。
- **按稿子行播放**：默认**一行 = 一个播放/合成单元**（不再按句号把一行拆成碎块）。上传的实录稿一行就是一段话，按句拆会产生几百个碎块、每块自带边界与停顿。单行超过 400 字才自动按句号细分；行内的 `[[pause:…]]`、`[[no interrupt]]`、`[[待插:…]]` 仍按标记切分。你那份 118 行的稿：按句拆是 350 段，现在按行是 157 段。
- **多稿轮换（默认不开、界面上不显示）**：能力保留在 `orchestrator.py`——若开启，可设「每套最多播 N 行」或「每套最多播 N 分钟」，任一条件先到就在句子边界切到稿子库的下一套，切换后自动为新稿预生成、生成过的行直接命中缓存。稿子库不足 2 套时不切。
- **播放**：底部「▶ 开始连续播放（外放）」按钮，自动接播新生成的音频块（不会重播历史块）。开播手机靠近这台设备扬声器即可收音。

`--room` 填 `live.douyin.com/` 后面的数字或直播间分享链接。程序会自动：
解析真实 room_id → 生成 webcast 签名（vendor/sign.js，mini-racer；**没有 mini-racer 时自动回退到本机 `node` 子进程**，签名一致）→ 连 `wss://webcast100-ws-web-lq.douyin.com/webcast/im/push/v2/` → gzip+protobuf 解析互动消息（房间未开播时自动轮询重试，断线自动重连）。

## 能不能不打云端、直接当 App 用？

结论：**可以，不需要任何云端服务**。整套系统只有三个外部依赖，全部不需要你部署：

| 依赖 | 是否必须云端 | 说明 |
|---|---|---|
| 抖音互动采集 | 否 | 直连抖音官方 websocket，纯客户端 |
| 语音合成 / 复刻音色 | 只用百炼 API | 唯一需要填 Key 的地方；音频不在本地生成模型 |
| 播放 | 否 | 本机扬声器外放 |

服务端只是**你本机跑的一个小 HTTP 服务**（`web/console.py`），手机浏览器打开它。所以"打包成 App"有三条现成路线：

1. **浏览器 PWA（最简单，零改造）**：手机 Chrome 打开控制台 → 菜单「添加到主屏幕」。图标、全屏、免地址栏，体验接近 App。
2. **手机本机运行（真正免电脑）**：Termux 里 `pkg install python nodejs ffmpeg` → `uv sync` → 起 `web/console.py`，同一台手机既采集又合成又外放。签名模块已支持 node 回退，ffmpeg 用来把录音转成百炼要求的 wav——这条路线已在这台机器上完整验证过（无 .env、纯页面填 Key、录音格式 webm→wav→复刻→合成全通）。要做成 APK 可用 Termux:Boot 自启 + Chatterboard/termux-alarm 类壳，或 Python 的 Briefcase/Kivy 包装。
3. **要真正的原生 App（商店上架）**：把 `src/airadio` 编译进手机 App（Python 用 ChaquoPy/Briefcase）或用同一套协议用 Kotlin/Swift 重写采集层。工作量最大，收益只是更"像 App"，功能上和 1、2 没区别。

不建议做的形态：**部署到云服务器 + 手机访问**。因为音频要在开播手机旁边外放，云端出声音反而要多一跳，且抖音房间采集本身是客户端行为，云端没有任何收益。

唯一必须联网的是百炼 API（合成/复刻）和抖音（互动）。稿子、调度、缓存、播放全在本地，稿子不变时循环**零 API 调用**（实测：44 个音频块只请求了 12 次 TTS）。

## 直播稿标记语法

```text
普通的一行一句。              ← 按。！？…切句；句与句之间才是插播点
[[no interrupt]]报价、政策、金句不许被打断。[[/no interrupt]]
[[pause:800]]                ← 定点停顿 0.8 秒
[[待插:感谢{nick}的支持]]     ← 固定位置必播话术（{nick}/{gift} 占位符取最近互动）
# 小节标题                    ← 渲染成"接下来，小节标题。"
一整行不写句号就是一整句     ← 整段不可插播打断（另一种"不可插播"写法）
```

核心保证：**句子中间永远不会被插播打断**——插播只发生在句边界；保护块内的句子边界也被禁用。

## 插播调度参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--window 60,150` | 60–150s | 全局默认：每个互动事件分配"计划插播时刻"=事件时间+随机区间，到点后的句边界才插 → 天然随机、不机械 |
| `--kind-window "gift=15,40;chat=20,50;like=90,180"` | 无 | **每类互动独立的随机区间**（礼物快、点赞慢），未配置的类跟随全局 window；控制台也有对应输入框 |
| 优先级 | 礼物>弹幕>关注>进场>点赞 | 同一批到期事件按优先级取，同级内**只取最新几条**（`max_events` 默认 3），旧的过期即弃 |
| `--min-gap 45` | 45s | 两次插播最小间隔 |
| `--prefetch 3` | 3 | 自动提前预生成后面 N 句（0=关闭，纯边播边合成）；`--prefetch-all` 启动时先把整稿全部合成 |
| 礼物插队 | ≥100钻石 | 高价值礼物（火箭/嘉年华等）等 12s 左右即可插队，不等窗口 |
| 兜底话术 | 180s | 长时间无互动时播一段引导点赞关注的兜底话 |
| 事件时效 | 90s | 只念 90 秒内的新事件；重复事件签名去重，绝不重播 |

## TTS 缓存与循环

稿子默认无限循环播（`--loops 0`）。**稿子没变的句子只在第一轮真实合成一次**，之后循环直接复用缓存音频——只有新的互动插播才调用百炼，长时间直播 API 成本 ≈ 插播次数。缓存 key 含模型/音色/语速：换音色或语速后旧缓存自动失效、按需重新重新合成；控制台状态栏实时显示 `TTS调用 / 缓存复用` 计数。实测：第二轮起 chunks 继续增长而 tts_calls 不再增长。

## 音频进直播间的三种接法（按落地成本排序）

1. **一部手机开播 + 另一台设备外放**（推荐起步）：跑本系统的电脑或**第二部手机**开播放页外放，开播手机靠近扬声器，麦克风直接收音。零硬件成本，马上能用。
2. **同一台电脑开播+播放，走虚拟声卡**：装 VB-Cable/Voicemeeter，抖音开播客户端的麦克风源选虚拟声卡，本系统 `--sink ffplay` 输出到该声卡。音质干净、无环境串音。
3. **两部手机**：一部跑系统外放、一部开播收音（或开播用手机、第二部跑播放页）。两设备物理隔离，最稳，适合长时间直播。

服务端不能把音频直接推入抖音开播端，所以"播放设备→麦克风"是正确通路；外放是最快落地，双手机是最终形态。

## 技术要点

- **互动消息**：抖音网页端直播间的 websocket 协议（webcast/im/push/v2，protobuf + gzip），事件含进场、关注、点赞、礼物、弹幕、灯牌(粉丝团)。字段号用真实抓包核对（`scripts/sample_frames.json`），协议回归测试在 `tests/test_timeline.py::test_captured_samples_parse`。
- **礼物必须登录**：抖音服务端只向带登录 Cookie（`sessionid_ss`/`sessionid`/`sid_tt`）的连接下发 `WebcastGiftMessage`；游客态只收到弹幕/进场/关注/点赞/灯牌/人数，一条礼物都没有（实测 4 房间 ×40–100s，gift=0）。登录 Cookie 要放在 **WSS 握手的 header**，不是 URL 参数；没有 `need_landing_params`/`x-tt-*` 之类的参数能替代。用法：浏览器登录 live.douyin.com → F12 → Network → 复制任意请求的整行 Cookie → 控制台「抖音登录 Cookie」框或 `--douyin-cookie`/`DOUYIN_COOKIE`。没有它其它互动照常工作。
- **签名**：webcast 连接需要 sign.js 生成的 signature（`src/airadio/sign.py`，mini-racer 执行 vendor/sign.js），路线与开源 DouyinLiveWebFetcher 一致。
- **TTS**：dashscope `tts_v2.SpeechSynthesizer`，cosyvoice-v2 流式合成（一次句/插播 = 一次 task），`--voice` 换音色（longxiaochun_v2 女 / longcheng_v2 男等），`--rate` 语速 0.5–2。
- **离线可开发**：`--sink dry` 不需要百炼 Key，可完整验证采集与调度。

## 已知限制

- 抖音 webcast 是网页端逆向协议，非官方 API：抖音改版可能需要更新 room_id 解析或签名脚本（`scripts/capture_frames.py` 可重抓样本回归）。
- 直播间必须开播中；未开播时程序每 30s 自动重试解析。
- 一个抖音登录 Cookie 同一时刻只对一个直播间有效：多房间共用同一 Cookie 会被互相踢掉登录态、礼物消失（需要每房间一个账号的 Cookie，或改用浏览器内核）。Cookie 过期或账号被风控的典型现象是「只收到一条礼物之后不再有」。
- 评论插播默认截断到 40 字（避免长弹幕拖节奏），`ScheduleConfig.chat_max_len` 可调。
